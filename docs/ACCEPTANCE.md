# قائمة القبول — Loomix مقابل المواصفة

حالة كل بند كما نعرفها اليوم. المصطلحات:

- **مُتحقَّق:** نُفِّذ في الكود، وشُغِّل فعليًا عبر HTTP أو سكربت، ونتيجته معروفة.
- **مُنفَّذ:** موجود في الكود، ولم يُشغَّل في هذه البيئة.
- **غير مُتحقَّق:** يعتمد على بيئة لا نملكها (متصفح حقيقي، نشر فعلي، مفاتيح خارجية).

> نتائج الجولة الكاملة (الأرقام والأوامر) في `docs/VERIFICATION.md`.
>
> لا يوجد متصفح في بيئة البناء. كل «تحقّق» هنا يستند إلى استجابات HTTP، وHTML المُصيَّر،
> وفحوص قاعدة البيانات، واستدعاء إجراءات الخادم مباشرة. لا ندّعي أي فحص بصري.

## 2. خريطة الموقع (§3)

كل المسارات موجودة: `/` · `/movies` · `/series` · `/anime` · `/latest` · `/trending` · `/top-rated` ·
`/most-viewed` · `/genre/[slug]` · `/year/[year]` · `/country/[code]` · `/search` · `/movie/[slug]` ·
`/series/[slug]` · `/series/[slug]/season/[n]` · `.../episode/[m]` · `/trailers` · `/person/[slug]` ·
`/watchlist` · `/login` · `/register` · `/profile` · `/privacy-policy` · `/terms` · `/dmca` · `/contact` · 404 · 500 (global-error).

- **مُتحقَّق:** زحف 220 رابطًا من `sitemap.xml` → كلها 200، وصفر روابط مكسورة.
- **404 حقيقي:** `/movie/<غير موجود>`, `/series/...`, `/anime/...`, موسم/حلقة/شخص/تصنيف/سنة
  غير موجودة → كلها **404** لا 200، مع `noindex` وعنوان «الصفحة غير موجودة — لوميكس».
  ملاحظة موثّقة: Next يضيف `<meta name="robots" content="noindex">` تلقائيًا لصفحات 404،
  وصفحتنا تضيف `noindex, follow` فوقه، فيظهر وسمان **متسقان** (كلاهما يمنع الفهرسة، والثاني
  يسمح بتتبّع الروابط). إزالة وسمنا تجعل وسوم التخطيط العام `index, follow` تظهر مع `noindex`
  فتتناقض — لذلك يُبقى الوسم.
  **مُتحقَّق** على 11 مسارًا، و`npm run smoke` يفحص الثلاثة معًا (كود + noindex + العنوان).
- **قيد مُوثَّق:** في المسارات الديناميكية يُرسل Next صفحة 404 كواجهة عبر تدفّق RSC، أي أن
  **رمز الحالة صحيح ومحتوى 404 يظهر مع JavaScript**، أما بدونه فالهيكل يبقى فارغًا. أثبتنا أن
  السبب سلوك إطار العمل لا كودنا: مسار تجريبي أدنى (صفحة واحدة + `notFound()`، بلا تخطيط ولا قاعدة
  بيانات) أعطى النتيجة نفسها. الصفحات غير الموجودة أصلًا (مثل `/totally-missing`) تُصيَّر كاملة من
  الخادم لأن Next يحلّ 404 قبل بدء التدفّق.
- **ترقيم الصفحات:** `?page=999` يعطي 200 مع حالة صريحة «لا توجد صفحة بهذا الرقم» وزر «الصفحة
  الأولى» — لا صفحة فارغة ولا خطأ. `?page=0` و`?page=abc` يعودان للصفحة الأولى.
- **canonical للترقيم:** الصفحة الأولى هي المرجع (`/movies`)، وكل عمل له صفحته الخاصة في الخريطة،
  فلا تعتمد فهرسة الأعمال على تسلسل صفحات القوائم.
- **`/most-viewed`** لا يعرض شيئًا قبل وجود مشاهدات حقيقية (`views_count >= 1`) ويشرح السبب.
- **مُتحقَّق (عدّاد المشاهدات):** `POST /api/views` يعيد 200، والرابع في الساعة لنفس IP+العمل يعيد 429،
  والجسم المشوّه 400، والمعرّف المجهول 404. بعد أول مشاهدة ظهر العمل في `/most-viewed`، وبعد تصفير
  العدّاد عادت الحالة الفارغة — أي أن القائمة تقرأ العدّاد فعليًا لا شيئًا مُعدًّا مسبقًا.

## 4. اللوحة (§10) — 28 مسارًا

| الوظيفة | الحالة |
|---|---|
| دخول/خروج وإدارة الجلسة | **مُتحقَّق**: 303 بعد الدخول، كوكي `HttpOnly; Secure; SameSite=Lax`، صلاحية 12 ساعة للإدارة |
| RBAC | **مُتحقَّق**: مشاهد على `/admin` → 307 إلى `/?forbidden=admin`؛ رفع ملفات كـمشاهد → 403؛ مجهول → 401 |
| إنشاء عمل | **مُتحقَّق** (POST حقيقي ← 303 ← ظهور في اللوحة والواجهة والخريطة) |
| تعديل عمل | **مُتحقَّق**: حفظ الحقل، ظهوره في اللوحة وفي صفحة العمل فورًا (إبطال الكاش)، ثم استرجاع |
| حذف عمل | **مُتحقَّق**: اختفى من اللوحة، صفحته والإدارة 404، وسجل تدقيق `TITLE_DELETE` |
| استيراد CSV/JSON مجزّأ | **مُتحقَّق**: تحليل ← تقرير أخطاء عربي لكل صف ← دفعات 10 صفوف ← منع التكرار ← التكرار لا يعيد المعالجة |
| المواسم والحلقات | **مُتحقَّق**: إنشاء/تعديل موسم، رفض الرقم المكرر برسالة عربية، إنشاء حلقة، رفض الرقم المكرر، إضافة دفعة 3 حلقات كمسودات، إعادة الدفعة لا تكرّرها |
| الأشخاص والتصنيفات | **مُتحقَّق**: إنشاء شخص وتعديله وحذفه؛ إنشاء تصنيف وحذفه مع منع الحذف قبل إعادة التصنيف |
| التريلرات | **مُتحقَّق**: إضافة، تعيين الأساسي (تبدّل الفيديو في صفحة العمل فورًا)، حذف؛ فحص الصحة بلا شبكة يُبقي الحالة «لم يُفحص» برسالة صريحة |
| التحديث الجماعي | **مُتحقَّق**: حماية التعديل اليدوي تُخطّي الأعمال المحمية، والتقرير يعرض قبل→بعد، والسبب في سجل العمليات |
| أقسام الرئيسية | **مُتحقَّق**: إخفاء قسم يزيله من الصفحة فورًا، وإرجاعه يعيده، والترتيب يتغيّر بالحركة |
| قوائم الترند/اختيارات المحرر | **مُتحقَّق**: إضافة عمل، منع التكرار برسالة، التثبيت (pinned) يرفعه للأول، الحذف يُرجع العدد |
| المستخدمون والأدوار | **مُتحقَّق**: إنشاء حساب، رفض بريد مكرر، رفض كلمة مرور قصيرة، تغيير الدور، تعطيل/تفعيل، حذف، وإعادة تعيين كلمة المرور بمساعدة الإدارة (صفحة مستقلة `/admin/users/[id]/password`، إبطال الجلسات، وسجل `USER_PASSWORD_RESET`) |
| إعدادات SEO | **مُتحقَّق**: إطفاء فهرسة الأعمال يضيف `noindex` على صفحة العمل فورًا، وإرجاعه يزيله |
| التنقل والتذييل | **مُتحقَّق**: تغيير تسمية يظهر في الرأس مباشرة، الروابط الخارجية مرفوضة برسالة عربية |
| نسخ احتياطي واستعادة | **مُتحقَّق** (18 جدولًا / 547 صفًا ذهابًا وعودة) |
| رفع الصور | **مُتحقَّق**: WebP صالح ← 200 مع نسختين 400/900؛ نص متنكّر كـPNG ← 415 بفحص البايتات؛ أكبر من 6MB ← 413 |
| صندوق الرسائل وDMCA | **مُتحقَّق**: 5 رسائل ناجحة ثم حجب، حقل المصيدة لا يُدرج، والرسائل تظهر في اللوحة |
| سجل التدقيق | **مُتحقَّق**: صفوف الدخول/التعديل/الحذف/الاستيراد/الرسائل، وكل حدث (49 حدثًا) له تسمية عربية — يتحقّق منها `npm run preflight` ثابتًا |
| المصادر الخارجية (API) | معطّلة عن قصد؛ الصفحة تُظهر وجود المفتاح لا قيمته |
| الإعلانات | غير مبنية (خارج النطاق حسب المواصفة) |
| ترتيب الأقسام والرائج بالسحب | **المنطق مُتحقَّق** (أزرار الحركة تعمل)، والسحب نفسه غير مُتحقَّق (يحتاج متصفحًا) |

**بلا JavaScript:** نماذج الإضافة والتعديل **تعمل**، وكذلك **النشر/إلغاء النشر من صف القائمة**
(نموذج `action={serverAction}` يُصدر معرّف الإجراء داخل HTML)، و**الحذف** صار عبر صفحة تأكيد
`/admin/titles/[id]/delete` تعرض ما سيُحذف معه ثم نموذجًا حقيقيًا.

**مُتحقَّق بالكامل بلا سكربتات (POST أصلي):** إنشاء عمل `nojs-flow-check` (303) ← ظهوره مسودة
فتُعيد صفحته 404 ← النشر من صف القائمة ← صفحته 200 ← صفحة التأكيد 200 وفيها تحذير الحذف ←
الحذف 303 إلى `?deleted=1` ← الصفحة 404 ولوحة التحرير 404 والرابط غائب من `sitemap.xml`.

**كل إجراءات الصفوف في اللوحة تعمل بلا JS الآن** بعد تحويل المكوّنات إلى نماذج خادم حقيقية
(`RowActionForm` + `useFormStatus`): حذف الموسم/الحلقة/الشخص/التريلر/المستخدم، تعيين التريلر
الأساسي ووسمه، تغيير دور المستخدم وتفعيله/إيقافه، وتغيير حالة رسالة.

**مُتحقَّق بـPOST أصلي:** إيقاف حساب المشاهد ثم تفعيله، تغيير حالة رسالة ثم إرجاعها، وتعيين تريلر
ثانوي «أساسيًا» ثم إرجاع الأساسي الأصلي (بالقاعدة). حُذفت آثار الاختبار كلها.

ما يبقى بحاجة إلى JS: السحب والترتيب بالماوس، واختيار التصنيفات والأشخاص داخل نموذج العمل،
ومعاينة الصور، ونتيجة «فحص الرابط» الفورية (الفحص نفسه يُنفَّذ ويُحدَّث الصف).

## 5. الأمان (§11)

- bcrypt (12 جولة) وجلسات عشوائية 32 بايت مُخزَّنة مُجزَّأة — مُتحقَّق.
- **انتهاء الجلسة على الخادم:** صف جلسة `expires_at` في الماضي → `/admin` يعيد **307 إلى
  `/login?next=/admin`** (اختُبر بإيقاف الخادم ثم تعديل الصف ثم تشغيله — لا يمكن اختبارها والخادم يعمل
  لأن PGlite عملية واحدة).
- **تغيير كلمة المرور يُبطل كل الجلسات فورًا:** بعد التغيير صار الكوكي القديم **307** إلى الدخول،
  وكلمة المرور القديمة **مرفوضة**، والجديدة تنجح (303). البيانات أُعيدت بعد الاختبار.
- حدود المعدل: تسجيل الدخول (10/10د لكل IP)، التواصل (5/ساعة)، المشاهدات (3/ساعة لكل IP+عمل)،
  والبحث — مُتحقَّق بصدّ فعلي (429 أو رسالة حجب).
- حقل المصيدة في نموذج التواصل — مُتحقَّق (ردّ نجاح كاذب بلا إدراج).
- CSP + HSTS + `X-Frame-Options` + `Referrer-Policy` + `Permissions-Policy` — مُتحقَّق بالاستجابة.
- أسرار الخادم لا تظهر في أي صفحة؛ بيانات الدخول التجريبية تُعرض فقط عند `SHOW_DEMO_CREDENTIALS=1`.
- سجل التدقيق للقراءة فقط من الواجهة.
- **حارس صفحات المدير العام على الخادم (2026-10-21):** `/admin/users` و`/admin/seo` و`/admin/backup`
  كانت مخفية من الشريط الجانبي للمحرر لكنها تُفتح بالرابط المباشر (200). أُضيف `requireAdminPage()`
  في `lib/auth.ts`، والآن المحرر يُحوَّل إلى `/?forbidden=admin`. **مُتحقَّق**.
- **إعادة تعيين كلمة مرور مستخدم (جديدة):** مقصورة على المدير العام — المحرر يُحوَّل **307** إلى
  `/?forbidden=admin`، والتأكيد غير المطابق يرد برسالة عربية بلا تغيير. بعد التعيين تُحذف جلسات
  الحساب فورًا (كوكي المشاهد القديم → **307** إلى الدخول)، وكلمة المرور القديمة تُرفض والجديدة تنجح.
  **مُتحقَّق** بلا JavaScript (POST أصلي + 303 مع لافتة نجاح)، ثم أُعيدت كلمة المرور الأصلية.
- **تصعيد الصلاحيات عبر إجراء مسموح:** المحرر يملك صفحة إعدادات الموقع، وكان يمكنه تمرير مفاتيح SEO
  (`seo_index_*`) في نفس الطلب. أُضيف حارس في `saveSiteSettingsAction` يرد
  «إعدادات SEO والفهرسة تتطلب صلاحية مدير عام.» **مُتحقَّق بإرسال فعلي:** الردّ حمل الرسالة، وبقيت
  صفحة العمل مفهرسة. `listBackupsAction` كان بلا حارس إطلاقًا → صار يتطلب مديرًا.
- **مسح شامل لكل مسارات اللوحة (28 مسارًا):** بلا جلسة **307 → /login**، وبجلسة مشاهد
  **307 → /?forbidden=admin**، لا استثناء. **مُتحقَّق داخل `npm run e2e`.**
- **حدّ محاولات الدخول قابل للضبط في بيئات الاختبار فقط:** `RATE_LIMIT_LOGIN_MAX` (الافتراضي 10 لكل
  IP في 10 دقائق، والحد الأقصى 200). أُضيف لأن تشغيل `e2e` أكثر من 3 مرات في 10 دقائق كان يستهلك
  الحدّ ويظهر كفشل RBAC مضلّل. **لا يُضبط في الإنتاج**؛ عند تجاوز الحد يطبع `e2e` سبب الحجب وخطوات
  التنظيف بدل رسالة عامة.

## 7. SEO (§15)

- عنوان ووصف فريدان، canonical، `sitemap.xml` (220 رابطًا كلها 200، 37 `lastmod`)،
  `robots.txt` يمنع `/admin` و`/search` — مُتحقَّق.
- **كل الأوصاف داخل 70–165 حرفًا وبلا تكرار** على 220/220 صفحة (الوسيط 132)، بما فيها الصفحات
  المولّدة تلقائيًا للأشخاص والمواسم والحلقات والتصنيفات — **مُتحقَّق** عبر `npm run seo:audit`
  (بوابة تُخرج كود 1 عند المخالفة، اختُبرت سلبيًا).
- Schema.org من حقول حقيقية: `datePublished` بتاريخ كامل فقط، و`aggregateRating` مشروط بمصدر — مُتحقَّق.
- `Organization` + `WebSite` + `SearchAction` على مستوى الموقع في كل الصفحات (JSON صالح مُختبَر على 4 مسارات) — مُتحقَّق.
- **بيانات منظّمة لصفحات القوائم** (CollectionPage + ItemList + BreadcrumbList) على 12 مسارًا:
  `/movies` `/series` `/anime` `/latest` `/trending` `/top-rated` `/most-viewed` `/trailers`
  `/genre/[slug]` `/year/[year]` `/country/[code]`، وBreadcrumbList على `/person/[slug]`.
  **مُتحقَّق:** كل الكتل تُحلَّل كـJSON، و`url` مطلق، وروابط العناصر تعيد 200.
- **الأرقام في البيانات المنظّمة من القاعدة نفسها**، طابقناها صفًا بصف:

## 9. ما لم يُتحقَّق إطلاقًا

1. نشر فعلي (Vercel / Postgres مُدارة). مسار تخزين Vercel Blob **مكتوب ومربوط** لكنه لم يُجرَّب
   برفع حقيقي (لا توكن)؛ المسار المحلي مُختبَر.
2. مزامنة TMDB أو أي مصدر خارجي بمفتاح حقيقي.
3. العمل البصري: التناسق، التراكب، سلوك الهاتف.
4. السحب والإفلات بالماوس/اللمس (أزرار الترتيب تعمل، والسحب نفسه غير مُختبر).
5. ~~الإجراءات السريعة في قوائم اللوحة بلا JavaScript~~ — **أُنجزت**: كل إجراءات الصفوف صارت نماذج
   خادم تعمل بـPOST أصلي (تحقّقنا فعليًا على المستخدمين/الرسائل/التريلرات).
6. **استعادة كلمة المرور الذاتية غير موجودة**: لا بريد صادر في هذه النسخة، فالمسار المتاح هو
   إعادة التعيين بمساعدة الإدارة من اللوحة (مُتحقَّق)، أو `npm run admin:password` للحسابات الإدارية.

## 12. صفحة 500 — ما تحقّق فعليًا

أُضيف `app/global-error.tsx`: صفحة 500 عربية بهوية الموقع تحلّ محل التخطيط الجذري كاملًا
(بأنماط سطرية، لأن Tailwind قد لا تكون محمّلة عند فشل التخطيط).

**ما قِسناه** بمسار مؤقت يرمي استثناءً أثناء العرض:

| الفحص | النتيجة |
|---|---|
| كود الاستجابة | **500** (لا 200 ولا 404) |
| تسريب رسالة الخطأ أو stack للعميل | **لا شيء** — الرسالة في سجل الخادم فقط |
| `digest` للمتابعة في السجلات | موجود في الحمولة |
| الصفحة المخصّصة في حزمة العميل | موجودة (`global-error-*.js` يحوي «تعذّر تشغيل الصفحة») |

**حدود خطأ داخل الأقسام (2026-10-21):** أُضيف `app/(site)/error.tsx` و`app/(admin)/error.tsx`.
الحدّ الجذري `app/error.tsx` يقع فوق تخطيطات الأقسام، فكان أي خطأ يستبدل رأس الموقع وشريط اللوحة
بصفحة كاملة. الحدّان الجديدان يعيشان داخل التخطيط فيبقى التنقل متاحًا. **مُتحقَّق بنيويًا:** مسار
الخطأ في `page_client-reference-manifest` لكل قسم يشير إلى ملفه، وحِزَم العميل
`app/(site)/error-*.js` و`app/(admin)/error-*.js` موجودة وتحوي النص العربي.
**غير مُتحقَّق:** الرسم الفعلي في متصفح (الحدّ يُرسم على العميل، و`curl` يرى هيكلًا فارغًا).

**404 داخل اللوحة:** أُضيف `app/(admin)/admin/not-found.tsx`. **مُتحقَّق:** معرّف عمل غير موجود
يعيد **404** ويحمل نص «هذا العنصر غير موجود» وروابط داخل اللوحة، بدل 404 العام. ملاحظة مقيسة:
بإضافة `loading.tsx` لقسم اللوحة يصبح الرمز **200** لأن التدفّق يبدأ قبل `notFound()`؛ لذلك
لم يُضف (صحة رمز الحالة أولى من هيكل تحميل داخلي).

**قيد مُوثَّق:** عند استثناء من الخادم يعيد Next هيكلًا فارغًا (بلا نص مرئي) ثم يرسم
`global-error` بعد التحميل. أي أن صفحة 500 المصمّمة **تظهر مع JavaScript فقط**، وبلا JS يرى
الزائر صفحة فارغة من المنصة. لا يوجد في Next طريقة لتقديم محتوى خطأ مُصيَّر من الخادم لهذه الحالة،
فلا ندّعي غير ذلك.
